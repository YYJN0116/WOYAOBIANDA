## 2. 本期完成的核心工作

### 2.1 训练交互体验重构（用户反馈第一项）

#### (1) 点击“开始训练”直达训练记录界面
- **原逻辑**：首页点击“开始训练”强行先进入“训练计划页面”（`workout-plan`），用户需再次点击才能开始。
- **现逻辑**：
  - 点击“开始训练”后，自动读取已选定的动作组合，直接进入 `workout-session` 开始训练。
  - 若用户初次使用尚未选定动作，平滑降级至推荐动作选择页（`workout-result`）。
  - “训练计划”仍保留在首页次级按钮中，供用户随时查看或规划整周安排。

#### (2) 减少每组打卡确认次数（紧凑表格 + 一键完成动作）
- **原逻辑**：每个动作的每组均为独立卡片，包含重量选择、次数输入、以及“标记本组完成”按钮，多组动作需要繁琐的多次上下滚动与逐个点击。
- **现逻辑**：
  - **紧凑表格布局**：单屏集中展示当前动作所有组（组号、重量输入、次数输入、单组勾选状态）。
  - **一键完成整组动作**：底部提供“完成本动作（全部 N 组）”显目按钮，支持一键确认全部已填组数并无缝推进到下一个动作或训练总结。
  - **保留逐组微调**：行内右侧仍提供单组“✓/○”快速勾选，满足对某一特定组精确调整的需求。

### 2.2 关键架构缺陷与运行时 Bug 诊断修复

在真机/模拟器测试与路由跳转过程中，定位并彻底修复了三项严重影响使用的底层问题：

#### (1) 修复 `Cannot update a component (RoutingQueueProvider) while rendering a different component`
- **原因分析**：在 React 19 / React Native 新架构下，`setState` updater 函数必须是纯函数。原实现中在 `setSetsState` 的 reducer 内部直接调用了 `finishExercise`（内部调用 `router.replace`）以及 `AsyncStorage.setItem`，导致在当前组件计算状态时触发了外部导航上下文的重新渲染，引发 React 报错。
- **解决方案**：将路由推进与异步持久化操作全部移到事件处理流程的主体中，与纯状态更新彻底解耦。

#### (2) 根除 iOS 原生“More”选项卡与误跳“训练计划”
- **原因分析**：原生端 `app-tabs.tsx` 使用了 Expo Router 的 `NativeTabs`（对应 iOS UIKit 的 `UITabBarController`）。代码中把 12 个页面（含欢迎页、训练计划、总结、历史等流程页）全部注册为 Tab。iOS 系统限制底栏最多容纳 5 个标签，超出部分会自动被系统折叠为一个自带的 **"More..."（三点）选项卡**，点击 More 还会因 UIKit 行为直接跳转至“训练计划”，且内部子流程被底栏劫持。
- **解决方案**：
  - 将 `app-tabs.tsx` 重构为与 Web 端架构统一的 `expo-router/ui` 无头标签导航。
  - 底栏物理上**仅保留 `Home` 与 `Explore` 两个标签**，不再有任何“More”选项卡。
  - 所有内部流程页在布局中作为隐藏路由挂载，既具备全局直接导航能力，又绝不占用底栏。
  - 训练进行中时，通过 `isWorkoutFlow` 自动隐藏整个底栏，实现沉浸式训练。

#### (3) 修复“训练完成”保存卡死在“正在保存…”
- **原因分析**：
  - 历史记录读取函数 `loadCompletedWorkouts` 原本使用 `every(isCompletedWorkout)` 进行硬性校验。当设备本地存在旧版存储格式或某次异常字段（如包含 `NaN` 转成 `null`）时，读取直接抛出未捕获异常，导致保存流程中断。
  - 训练总结页在触发保存时未配置 `finally` 块，一旦发生异常或路由重定向未立即卸载，页面永久锁死在 `isSaving: true`。
- **解决方案**：
  - 在 `workout-preferences.ts` 中重构 `loadCompletedWorkouts`，支持容错清洗与缺省补全，即使有损坏或旧版条目也能正常过滤修复，**绝不抛错阻断保存**。
  - 在 `workout-summary.tsx` 中加入数据清洗（`Math.max(0, ... || 0)`）与 `finally { setIsSaving(false); }` 保护。
  - 保存成功后明确重定向至首页（`router.replace('/')`），流程完整闭环。

### 2.3 初始问卷增强与智能跳过路由

#### (1) 增加“每周训练天数”单选
- 在 `src/types/workout.ts` 中扩充 `FitnessProfile` 类型，增加 `weeklyDays: 3 | 4 | 5`。
- 在 `src/app/fitness-profile.tsx` 中增加“每周训练天数”单选题（3天 / 4天 / 5天），并具备必填校验。
- 问卷页面支持**数据回显**：用户二次进入时自动加载已存资料，无需重新填写。

#### (2) 全局初始化完成持久化标记
- 在 `workout-preferences.ts` 中增加存储键 `fitness-coach:profile-completed`。
- 当保存 `FitnessProfile` 成功后，自动调用 `completeProfile()` 将状态置为已完成。
- 提供 `loadProfileCompleted()` 供全局路由判定。

#### (3) 启动与入口防重复弹出问卷
- **App 启动入口（`index.tsx`）**：首次启动的全新用户才被导向问卷；已经完成过问卷的用户直接留在首页/训练相关页面。
- **点击“开始训练”**：已完成问卷的用户绝不再弹出问卷，若已选择动作直达训练，未选择动作直接进入部位选择。
- **欢迎页拦截（`welcome.tsx`）**：若已完成问卷的用户误入欢迎页，页面会自动重定向至训练流程，避免重复填写。
